# Інтеграція оплати Fit Beauty

Скопіюйте всі файли з архіву до кореня поточного репозиторію. Папку `api` також потрібно додати повністю.

## Налаштування Vercel

У Vercel відкрийте **Project Settings → Environment Variables** та додайте:

- `WFP_MERCHANT_ACCOUNT` — Merchant Login магазину WayForPay;
- `WFP_MERCHANT_SECRET_KEY` — Merchant Secret Key;
- `WFP_MERCHANT_DOMAIN` — домен без `https://`, наприклад `fit-beauty.vercel.app`;
- `SITE_URL` — повна адреса сайту, наприклад `https://fit-beauty.vercel.app`.
- `WFP_AMOUNT` — сума платежу: `1` для тесту, після перевірки змініть на `1290`.

Після додавання змінних виконайте новий Deploy.

Секретний ключ не можна вставляти в HTML, JavaScript браузера, `.env.example` або GitHub. Він має зберігатися лише у змінних середовища Vercel.

## Що входить

- `index.html` — у кнопках покупки встановлений перехід на `checkout.html`;
- `checkout.html` — форма і запуск захищеного віджета WayForPay;
- `thank-you.html` — підтвердження успішної оплати та кнопка Telegram-бота;
- `payment-error.html` — повідомлення про невдалу оплату, повторна спроба й підтримка;
- `payment-pending.html` — окремий екран очікування підтвердження оплати;
- `payment-pending.js` — автоматична перевірка статусу на екрані очікування;
- `payment.css`, `payment.js` — дизайн та логіка сторінок;
- `api/create-payment.js` — безпечне створення підписаного платежу;
- `api/payment-return.js` — приймає повернення з мобільної сторінки WayForPay та робить безпечний редирект;
- `api/wayforpay-callback.js` — перевірка підписаного повідомлення WayForPay;
- `api/payment-status.js` — повторна перевірка статусу платежу після відповіді `Pending`;
- `.env.example` — назви потрібних змінних без реальних секретів.

Ім’я, прізвище, телефон та email передаються у WayForPay із форми `checkout.html`. Поле ПІБ власника картки може залишатися у WayForPay як окреме банківське поле — це залежить від налаштувань мерчанта.

Якщо WayForPay спочатку повертає `Pending`, користувач переходить на окрему сторінку очікування. Для мобільної оплати `returnUrl` веде через `/api/payment-return`: маршрут приймає як `GET`, так і `POST`, тому Vercel не показує порожню сторінку при поверненні з WayForPay. Підписаний результат `Approved` одразу переводить на сторінку доступу, а `Pending` — на наш екран очікування. Додаткова фонова перевірка на `checkout.html` підхоплює результат, навіть якщо віджет не передав подію браузеру.

Сторінка очікування одразу перевіряє статус платежу. Статуси `Approved` і `Pending` переводять на сторінку успішної оплати та відкривають доступ до бота. Остаточна відмова (`Declined`, `Expired`, `Refunded` або `Voided`) переводить на сторінку помилки. Для інших проміжних статусів перевірка повторюється автоматично.
